# Validations: model guardrails, phase 1: message guard

All commands run from the repo root against a local Postgres (`npm run db:up`, `DATABASE_URL` pointing at it). Never a production URL or production `.env`.

## Must pass
- [ ] Workspace installs and the package is linked — check: `npm ci` exits 0 and `ls node_modules/@syraa/guardrails/package.json` exists.
- [ ] Lint, build and typecheck are green for the whole repo — check: `npm run check:ts` exits 0.
- [ ] All TypeScript tests pass, DB tests included — check: `npm run test:ts` exits 0 with `DATABASE_URL` set (the DB-backed files must run, not skip: output shows `repository.db.test.ts` passed).
- [ ] Core entry has no Mastra import — check: `grep -rn "@mastra" packages/guardrails/src` matches only `packages/guardrails/src/mastra.ts`.
- [ ] `callJev` behaves as the lesson gate's did: bearer key, `jev-latest`, 3 s default timeout, malformed answers throw — check: `packages/guardrails/tests/jev.test.ts` passes (mocked `fetch`: missing key throws `TYPESAFE_API_KEY not set`; HTTP 500 throws `jev HTTP 500`; an answer missing a question throws `jev answer missing: <name>`; request body has `model`, `state`, `questions`).
- [ ] `defineGuard.run` never rejects and is a no-op without a key — check: `guard.test.ts`: key unset resolves `null` and makes no `fetch` call; HTTP failure and timeout resolve a verdict with `state: "unchecked"` and a non-empty `error`; a decision with no flagged ids resolves `clean`; with flagged ids resolves `flagged` and `categories` equal to them.
- [ ] The reply is never delayed by the guard — check: `mastra.test.ts` runs an `Agent` with a mock model and a guard whose Jev call is a manually controlled deferred promise; `await result.consumeStream()` resolves while the deferred is still pending; afterwards resolving it makes `onVerdict` fire exactly once with the expected categories.
- [ ] A failing or throwing guard never breaks the turn — check: `mastra.test.ts`: `onVerdict` that throws, and a guard that fails, still let `consumeStream()` resolve and the saved assistant message be present.
- [ ] The processor classifies only the new user message, once per run — check: `mastra.test.ts` with a thread that already has history: the guard's `state` string contains only the new user text, and `run` is called once.
- [ ] No chat context means no work — check: `mastra.test.ts`: `resolveContext` returning `null` produces no `run` call and no `onVerdict`.
- [ ] `guardrail_verdicts` migration applies cleanly and twice — check: `node packages/guardrails/dist/migrate.js` run two times against the local DB exits 0 both times and `\d guardrail_verdicts` lists the table, both indexes and both check constraints.
- [ ] Message text is stored only for flagged rows — check: `repository.db.test.ts`: inserting a `clean` or `unchecked` row with `subjectText` set fails the `guardrail_verdicts_text_only_flagged` constraint; a `flagged` row stores it.
- [ ] Retention deletes only old verdict rows — check: `repository.db.test.ts`: rows 91 days old are removed by `purgeOlderThan(90)`, rows 89 days old and rows in `context_resources` are untouched (row counts before and after).
- [ ] The flag CLI lists flagged rows only — check: with one clean and one flagged row seeded, `npm run flags -w @syraa/guardrails` prints the flagged row (categories and text) and not the clean one.
- [ ] Lesson gate decisions are unchanged — check: the existing `packages/harness/tests/lesson-gate.test.ts` passes without edits to its assertions.
- [ ] Lesson gate Langfuse spans are unchanged — check: `packages/harness/tests/guardrails.test.ts` passes a fake parent span to `jevSpanTrace(parent, "classify-turn")` and asserts `createChildSpan` receives `{ type: SpanType.MODEL_INFERENCE, name: "classify-turn", input: { state, questions }, metadata: { jevCall: "classify-turn" }, attributes: { model: "jev-latest", provider: "typesafe" } }`, `end` receives `{ output: answers, attributes: { model, usage: { inputTokens, outputTokens } } }`, and a failure calls `span.error` with `endSpan: true`.
- [ ] Message decision rule — check: `guardrails.test.ts`: scores 0.79 do not flag, 0.8 flag, several flagged categories all returned, in the fixed order `jailbreak, abuse, harmful_request`.
- [ ] The agent has the processor attached — check: `guardrails.test.ts` asserts `createSyraaAgent({ tools: {} })` input processors include the one with id `guardrails`, and the tool-call eval still constructs the agent (`npm run typecheck -w @syraa/harness`).
- [ ] The Docker image builds with the new package — check: `docker build -t syraa-guardrails-check .` exits 0 (if Docker is unavailable, report that and verify instead by `grep -n guardrails Dockerfile docker/entrypoint.sh` showing the package.json copy, the source copy, the build line and the migrate line).
- [ ] CI covers the package — check: `grep -n guardrails .github/workflows/ci.yml` shows the build and migrate lines in `quality` and the build line in `agent-tool-calls`; `npm run check:ts` build order has guardrails before harness (`grep -n "@syraa/guardrails" package.json`).
- [ ] The live eval clears the bar — check: `~/.local/bin/infisical-run --env=personal -- npm run eval:guardrail -w @syraa/harness` exits 0, prints per-category precision of at least 0.9 for every category with positives, and the cases file has at least 60 labelled messages including near-miss negatives; the per-category precision and recall table is pasted into the PR description. If precision cannot reach 0.9, the phase is blocked and handed to the user (not silently relaxed).
- [ ] End-to-end on a local run — check: start the API locally with `TYPESAFE_API_KEY` loaded through `infisical-run`, send one benign and one jailbreak-style message through `POST /api/chat/stream`, then `npm run flags -w @syraa/guardrails` lists the jailbreak message and the `guardrail_verdicts` table holds a `clean` row for the benign one; the streamed responses are identical in shape with the guard on and off.
- [ ] Default-off behavior holds — check: with `TYPESAFE_API_KEY` unset, a chat turn completes and `SELECT count(*) FROM guardrail_verdicts` does not change.

## Negative checks
- [ ] No hook awaits Jev on the reply path — check: `grep -n "processOutputResult\|processOutputStream" packages/guardrails/src/mastra.ts` matches nothing, and the delayed-reply test above passes.
- [ ] Reply content is never altered or blocked — check: `grep -n "abort(\|tripwire\|TripWire" packages/guardrails/src` matches nothing.
- [ ] No duplicate Jev client remains in the harness — check: `grep -rn "api.typesafe.ai" packages/harness/src` matches nothing, and `grep -n "fetch(" packages/harness/src/lesson-gate.ts` matches nothing (the Jev URL and model constant live only in `packages/guardrails/src/jev.ts`; the harness imports `JEV_MODEL` from the package).
- [ ] No new third-party dependency beyond the package's listed `drizzle-orm`, `pg`, `@mastra/core` (peer/dev) and its dev tooling — check: `git diff package-lock.json` introduces no packages outside that set and their transitive dependencies already present in the lockfile; `packages/guardrails/package.json` dependency lists match step 1.
- [ ] No admin HTTP endpoint or role was added — check: `git diff -U0 packages/harness/src/server.ts` shows only the `startVerdictRetention()` call; `grep -rn "admin" packages/guardrails/src packages/harness/src/guardrails.ts` matches nothing.
- [ ] No text of non-flagged messages is persisted or logged — check: `grep -rn "console\." packages/guardrails/src packages/harness/src/guardrails.ts` shows no log line that includes message text (`text`, `subjectText`, `userMessage`).
- [ ] Out-of-scope packages untouched — check: `git diff --name-only dev...HEAD` (or `main...HEAD` if `dev` is absent) lists no file under `packages/context`, `packages/ingest`, `services/`, `apps/web`, and not `compose.yaml`.
